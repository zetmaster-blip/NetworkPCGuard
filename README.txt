 NetworkPCGuard  ネットワークPC外形監視（不正アクセス兆候）
 v1.0  ―  有限会社 丸枝 / 防御ツール一族
========================================================================

■ これは何か
  同一LAN上から「PCだけ」を抽出し、外側(ネットワーク側)から定期的に
  "外形ポート"を軽くスキャンして、前回との差分＝不正アクセスの「兆候」を
  検知するツールです。

  ・ ボタン一押しで、LAN上のPCを見つけて外形(開放ポート)を確認
  ・ 「定期監視 開始」で、指定間隔ごとに自動で再確認（アプリ常駐ループ）
  ・ 前回の正常な状態（ベースライン）と比べて、変化＝兆候を警告

------------------------------------------------------------------------
■ 大事な前提（正直な限界）  ★必ず読んでください
------------------------------------------------------------------------
  このツールが出すのは「外から見える変化 ＝ 侵入の"兆候"」であって、
  「実際に侵入され乗っ取られたか」の確証ではありません。

  たとえるなら、建物を"外から"見張るのと同じです。
    見える  … 新しいドア/窓が増えた（新しく開いた危険ポート）
              変な時間に灯りがついてる（想定外の状態）
    見えない… 中に誰がいて何をしているか（＝乗っ取りの確証）

  本当に乗っ取られたかは、そのPCの"中"＝ログイン履歴・イベントログ・
  プロセスを見る必要があります（それは ProcessGuard の領域）。

  → だから「高リスクの兆候」が出たら、それは「そのPCの中を調べる合図」です。
     兆候の多くは DHCP更新・メンテ・新しい機器の追加など正当な変化のことも
     あります。まず落ち着いて詳細を確認してください。

------------------------------------------------------------------------
■ 使い方
------------------------------------------------------------------------
  1. app.pyw をダブルクリックで起動（管理者権限は不要）。
  2. 対象サブネットを選択（既定ゲートウェイを持つLANが先頭）。
  3. 「▶ 今すぐ1回」で初回スキャン。
       → 初回は現在の状態を自動で「ベースライン」として保存します。
  4. 以降は「🔁 定期監視 開始」で、間隔(分)ごとに自動で再確認。
       前回との差分（兆候）を下段のリストに表示し、
       高リスクの兆候はポップアップで知らせます。
  5. ネットワークを整備して"新しい正常"になったら
       「✔ ベースライン更新」で現状を新しい基準として保存し直します。

  ・ 「PC以外の機器も表示」…既定はPCのみ表示。チェックで全機器表示。
  ・ 「📄 CSV」「🌐 HTML」…Excel用CSV / レポートHTMLを出力。
  ・ ダブルクリック or 「🔍 詳細」…その機器の開放ポートと判定理由を表示。

■ 判定の見方
------------------------------------------------------------------------
  判定列:
    PC濃厚      … Windows共有(135/139/445)/RDP/TTL128/PC向けNIC 等が揃う
    PCの可能性  … 一部の手がかりあり
    非PC(機器)  … カメラ/プリンタ/NAS/IoT等（メーカー・種別から）
    判定不能    … 手がかり不足（例: Mac/Linux/ポート全閉のPC は断定できない）

  危険度列:
    高 … 危険ポートが開いている（RDP/Telnet/VNC/TeamViewer/AnyDesk/
         Metasploit既定4444/DB(MySQL,MSSQL,Redis,Mongo等)/SOCKSプロキシ 等）
    中 … 平文サービス(Telnet/FTP/HTTP)の露出
    -  … 目立った危険ポートなし

  兆候(下段)の重大度:
    高 … 危険ポートが新規に開いた／危険ポート付きの新規PCが出現
    中 … ポート新規開放／新規PC出現／MACのIP移動／平文露出
    低 … ポート閉鎖／PC消失／ホスト名変化

------------------------------------------------------------------------
■ 自己診断（ツール自身の足音）  ★重要
------------------------------------------------------------------------
  このツールは各PCへ実際にTCP接続してポートを確認します。
  そのため、WiresharkAnalyzer や ルーターのIPS からは
  「ポートスキャン」として見えることがあります（＝自作の足音）。

  足音を抑える工夫:
    ・ 宛先はLAN内・応答のあった機器のみ
    ・ 厳選した約35ポートだけ（全ポート総当たりはしない）
    ・ TCP connect スキャンのみ（raw socket を使わない＝管理者権限不要）

  監視間隔を短くしすぎると足音が増えます。既定30分を目安に。

------------------------------------------------------------------------
■ 相棒ツール（役割分担）
------------------------------------------------------------------------
  NetworkDeviceList   … 全機器の棚卸し一覧（本ツールの探索エンジン流用元）
  WiresharkAnalyzer   … 通信の"中身"の異常（ビーコン/スキャン/平文）
  ProcessGuard        … このPC"自身"の内部（プロセス/署名/メモリ注入）
  arp_device_monitor  … なりすまし(ARP)の常時監視

  本ツールが埋める穴 = 「LAN上の"他のPC"を外から定期的にポート面で見張る」。

------------------------------------------------------------------------
■ ファイル構成
------------------------------------------------------------------------
  app.pyw          本体（Python標準ライブラリのみ・依存ゼロ）
  oui_ieee.json    ベンダー(OUI)判定DB（NetworkDeviceListから流用・約3.9万件）
  oui_user.json    ユーザー追加のメーカー定義（任意・{ "XX-XX-XX":[名前,種別] }）
  config.json      設定（間隔/タイムアウト/表示）※自動生成
  baseline.json    正常な基準状態 ※初回スキャン/ベースライン更新で生成
  alerts_log.csv   兆候の履歴（Excel用・追記）
  snapshots/       （予約）
  history/         各スキャンの記録（直近30件・JSON）

  ※ 開発実体は F ドライブ。OneDriveへは"日付名のバックアップ"のみ置くこと
     （baseline.json 等の固定名ファイルを複数PCで同期させると事故る）。
